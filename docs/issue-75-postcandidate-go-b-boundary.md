## GO B read-only live observer — bounded independent GET-only adapter

Implementation: [issue-75-go-b-live-readonly.py](../scripts/issue-75-go-b-live-readonly.py), [hostile tests](../tests/test-issue-75-go-b-live-readonly.py), invoked in the existing required build `resolver` CI. This adds an **independent read-only acquisition layer**, not another Publisher or another implementation of the signed topology predicate. It calls the already-accepted pure [publisher-preflight](../scripts/issue-75-publisher-preflight.py) `validate_snapshot()` without modifying its strict successful-job rules.

To audit a *future independently authorized* live signed promotion, run the standalone observer in a separately scoped read-only context, providing `GH_TOKEN` with minimum `actions:read` and `contents:read`, then pass the exact numeric `--run-id`. Never pass a Publisher writer token. The code invokes no `gh`, `git`, shell process, `POST`, `PATCH`, `DELETE`, tag/Release API, workflow dispatch or signer. **The observer cannot independently prove the scopes of a token provided by its caller**, so enforce least privilege in the surrounding job.

The observer obtains two separate GET copies (10 total responses) of the authenticated Run, attempt-specific job page, protected-main/required-App15368 rule, exact-main check runs, and immutable `promote.yml` from the run's fixed SHA; the workflow Git blob is independently hash-bound and both publisher checkout pins and signer pin are parsed. It rejects identity mismatch, non-main heads, incomplete/failed/synthetic attempts, partial pagination, duplicates, HTTP failure, conflicting snapshots, changed workflow/pin or non-`completed/success` required checks. It then calls `validate_snapshot()`, which demands the actual **authorize + signed PG-major build completed SUCCESS and Publisher currently in_progress**, not an unsigned `windows.yml` Run or the old GO A canary.

The output is intentionally **never** `GO_B=PASS`: even matching metadata would return only `LIVE_SIGNED_PUBLISHER_TOPOLOGY_METADATA_ONLY`, `BLOCKED_GO_B`, `signedArtifactsVerified=false`, `publishableReceipt=false`, `publicationAuthorized=false`, `writerEnabled=false`; exit code 2 also prevents a consumer from interpreting it as release approval. It does **not** fetch/verify signed ZIPs or SLSA/SPDX attestation bytes, mint a receipt, confirm human PUBLISH intent, prove writer credential isolation, approve a repin or change recovery schema v1. Unproven or altered pins remain `LEGACY_UNACCEPTED` or `UNAPPROVED_PIN_CHANGE` for future review only.
